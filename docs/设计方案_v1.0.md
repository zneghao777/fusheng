# 《浮生》整体设计方案 v1.0

> 文档类型：游戏设计文档（GDD）· 立项级
> 项目代号：浮生（Fusheng）
> 版本：v1.0 / 2026-10-19
> 适用范围：创意评审、MVP 排期、技术架构预研
> 说明：本文档只描述设计与架构思路，不包含代码实现。

## 0. 定位与设计支点

**一句话定位**：把"过日子"拆成一张可编排的日程表，让玩家用「计划 → 意外 → 回顾」的节奏，陪一个家族走过数代。

**目标体验**：一局 25–40 分钟能走完一个角色的一段人生；关掉网页时，心里留下"想看看他明天怎么样"的牵挂。

### 0.1 三个设计支点

每一个支点都必须能反推到具体功能，否则不写进文档。

| 支点 | 含义 | 反推出的功能 |
|---|---|---|
| **时间有重量** | 所有行为显式消耗时间，日程是核心决策界面，不是附属菜单 | 日程块编辑、时间三档、快进到下一日程块 |
| **关系会记事** | 关系数值之外必须有"记忆条目"，过去的行为要在未来产生回报或代价 | 三轴关系、记忆条目、对话选项由记忆解锁 |
| **家是表达** | 建造不是数值最优解，是玩家的自我表达画布，同时轻度反哺玩法 | 房间标签、情绪光环、蓝图分享 |

### 0.2 与《模拟人生》的差异点

不做"实时微观管理"，做"日程编排 + 关键干预"。这个差异决定了后面所有系统的形态：

1. **时间**：从"实时盯着"变成"排好计划、看它跑、在关键处插手"。
2. **情绪**：从单一情绪标签变成**二维情绪模型**（效价 × 唤醒），负面情绪也有玩法价值。
3. **会话**：Web 优先意味着短会话、可离线性、可分享（蓝图 / 家族树），而不是长时间沉浸。
4. **建造**：先给"一键套件"的结果，再给"自由模式"的自由。

### 0.3 贯穿全局的三条取舍原则

- **深度优先于广度**：宁可 4 个需求做出交互关系，也不要 8 个需求各自独立。
- **可解释优先于拟真**：玩家必须能一句话说清"他为什么难过"。
- **数据驱动优先于硬编码**：所有内容都是表，新增内容不改逻辑。

## 1. 核心玩法设计

### 1.1 游戏循环节奏：三层时间

生活模拟的难点在于"同时发生"与"玩家耐心"的矛盾。解法是把时间拆成三层，每层的粒度和玩家参与度不同。

| 层级 | 粒度 | 玩家做什么 | 反馈节奏 |
|---|---|---|---|
| **动作层** | 游戏分钟（5–120 分钟/次） | 点选物体 → 排队 → 看执行 | 秒级（动画 + 数值浮动） |
| **日程层** | 游戏小时（24 格/天） | 把日程块拖进时间轴 | 日终小结 |
| **人生层** | 天 / 年 / 代 | 生日、升学、婚育、传承 | 阶段结算 |

**推进方式**：连续 tick（1 游戏分钟 = 1 tick），1x 速度下 1 个游戏日约等于 12 分钟真实时间（1 tick ≈ 0.5 秒）。速度档位：暂停 / 1x / 3x / 快进到下一日程块 / 快进到下一事件。

**必须遵守的铁律**：任何需要玩家决策的事件，自动降速到暂停（auto-pause 白名单）。Web 端玩家随时会切标签页，这条是体验底线。

> **为什么不用纯回合制**：拟真生活需要"同时发生"的错觉——她在做饭，他在打电话。只有连续 tick 才能表现并行。
> **为什么不用纯实时**：网页端会话碎片化，必须有自动暂停 + 离线摘要兜底。

### 1.2 双环 + 双长环

| 环 | 时长 | 内容 | 爽点 |
|---|---|---|---|
| 短环 | 30 秒 | 选行动 → 执行 → 需求变化 → 微调 | 预期被满足 |
| 中环 | 1 天 | 排日程 → 应对 1–3 个意外 → 日终回顾 | 像翻一页手账 |
| 长环 | 1 代 | 技能 → 职业 → 关系沉淀 → 生育 / 传承 | 积累被看见 |
| 超长环 | 多代 | 家族声望、祖宅改造、传家物 | 意义感 |

**日终回顾是核心留存钩子**：每天结束时给一页"今天发生了什么"的自动叙事（3 条），比任何数值面板都更容易让人第二天再打开。

### 1.3 离线推进

玩家退出后，模拟按"摘要模式"继续跑（低精度、只结算关键事件）。回归时给一张卡片：这段时间发生了 1–3 件事，可花费"关注点"回看并做一次微调。

**设计理由**：Web 端必须"有进展但不惩罚"。惩罚性离线（回来发现角色崩溃）会直接导致流失；完全静止则失去"世界在运转"的错觉。

### 1.4 角色属性与需求系统

四层属性的周期不同，因此不会在同一时刻轰炸玩家——这是控制认知负荷的关键。

| 层 | 周期 | 数量 | 更新频率 |
|---|---|---|---|
| 需求 | 小时级 | 4 条 | 连续衰减 |
| 情绪 | 天级 | 8 象限 + 情绪源 | 事件驱动 |
| 技能 | 周级 | 10 条 | 行动累积 |
| 关系 | 代级 | 每人三轴 + 记忆 | 交互驱动 |

#### 1.4.1 需求：4 条，不是 8 条

| 需求 | 衰减速率 | 恢复手段 | 低于 25 的后果 |
|---|---|---|---|
| 体力 | -3.5 / 游戏小时 | 睡觉、小憩、咖啡 | 动作变慢、学习效率 -20% |
| 饱腹 | -4 / 游戏小时 | 正餐、零食、外卖 | 情绪下滑、社交成功率 -15% |
| 整洁 | -2 / 游戏小时 | 洗澡、洗手、换衣 | 他人好感获取 -30% |
| 兴致 | -2.5 / 游戏小时 | 娱乐、社交、审美环境 | 创造力下降、易触发"倦怠" |

**为什么是 4 条**：4 条是"一眼看完"的上限。把《模拟人生》里的"如厕 / 社交 / 卫生"折叠进"整洁"与"兴致"，减少机械打卡式操作。

**关键设计——需求不是红条，是效率乘数**：

- 需求 > 70：相关技能学习 +20%
- 需求 30–70：无修正
- 需求 < 30：相关行为 -30%
- 需求 < 10：**失控**（当场睡着、发脾气、暴食）

失控不是惩罚，是叙事材料。它是玩家"没照顾好自己"这一事实的可见后果，也是后续关系事件的触发源。

#### 1.4.2 情绪：二维模型

| 维度 | 范围 | 含义 |
|---|---|---|
| 效价（Valence） | -100 ~ +100 | 愉悦 ↔ 不悦 |
| 唤醒（Arousal） | 0 ~ 100 | 平静 ↔ 激动 |

两轴切成 8 个象限，每个象限解锁不同的行为与加成：

| 象限 | 情绪 | 行为倾向 | 玩法效果 |
|---|---|---|---|
| 高效价 · 高唤醒 | 兴奋 | 社交、冒险 | 社交成功率 +20%，易冲动消费 |
| 高效价 · 中唤醒 | 满足 | 日常 | 全技能 +10% |
| 高效价 · 低唤醒 | 平静 | 阅读、园艺 | 情绪恢复 +50% |
| 中效价 · 高唤醒 | 期待 | 计划、准备 | 日程执行效率 +15% |
| 低效价 · 高唤醒 | 愤怒 | 争吵、摔门 | 冲突选项解锁；"据理力争"可换晋升进度 |
| 低效价 · 中唤醒 | 烦躁 | 摸鱼、抱怨 | 工作效率 -20%，但"挑刺"能发现隐藏问题 |
| 低效价 · 低唤醒 | 低落 | 独处、创作 | **创作品质 +40%**，社交 -30% |
| 极低效价 · 低唤醒 | 疲惫 | 发呆、早睡 | 强制休息，次日体力上限 +10% |

**情绪源（Moodlet）**：每次情绪变化都来自具体来源，最多同时存在 5 个，各带强度（1–3 级）与半衰期（1–3 天）。

来源分三类：
- **环境**：房间标签（书房→专注）、光线（自然光→平静）、整洁度（脏乱→烦躁）
- **事件**：被表扬、吵架、升职、被放鸽子
- **需求缺口**：任一需求 < 25 时挂一个负面源

**设计理由**：让负面情绪有正收益（低落→创作、愤怒→谈判），玩家就不会只想把情绪刷满，而是开始"经营情绪"。这是本作与同类产品最大的差异点。

#### 1.4.3 技能：10 条主干 + 协同

主干：烹饪、体能、手作、园艺、音乐、写作、社交、逻辑、育儿、理财。

| 等级段 | 单级耗时 | 设计意图 |
|---|---|---|
| 1–3 级 | 约 10 分钟 | 快速给正反馈 |
| 4–6 级 | 约 1 小时 | 形成目标 |
| 7–9 级 | 数小时 | 长期投入 |
| 10 级 | 需"灵感时刻"（特定情绪 + 特定地点 + 特定道具） | 制造故事 |

**里程碑**：3 / 6 / 9 级各解锁一个特殊行为（如烹饪 6 级解锁"宴客"，可一次性提升全家关系）。

**技能协同（深度的主要来源，成本几乎为零）**：

| 组合 | 解锁 |
|---|---|
| 烹饪 5 + 园艺 4 | 自给自足：食材成本 -50% |
| 写作 6 + 逻辑 5 | 专栏：被动收入 + 声望 |
| 音乐 5 + 社交 6 | 街头演出：金钱 + 关系双收益 |
| 手作 6 + 理财 4 | 副业：可出售手作，单价随美观分提升 |

**生疏机制**：30 天未使用，不降级，只让"手感"临时 -20%，持续 2 天。避免惩罚性设计毁掉玩家投入。

#### 1.4.4 关系：三轴 + 记忆

| 轴 | 范围 | 作用 |
|---|---|---|
| 亲密 | 0–100 | 决定可用的互动类型（拥抱、倾诉） |
| 信任 | 0–100 | 决定是否分享秘密、是否被原谅 |
| 张力 | 0–100 | 决定冲突概率；高张力不等于坏事，它是戏剧燃料 |

**记忆条目**：每次有意义的交互写入一条（类型 / 强度 / 时间 / 是否已被提及），每人最多存 20 条，按强度衰减淘汰。

记忆直接进入玩法：
- 解锁对话选项（"他记得你在他失业时借过钱" → 可开口借钱）
- 改变事件权重（记仇 ≥ 3 条 → "翻旧账"事件）
- 影响和解难度（信任 40 时，需要 3 次正向交互才能消一条负记忆）

**关系状态机**：陌生 → 熟人 → 朋友 / 对手 → 亲密 / 仇敌 → 家人。每级解锁一组交互。

> **为什么不用单一友好度**：单一数值无法表达"我很爱他，但我不信任他"，而后者才是好剧情。

### 1.5 代际成长机制

#### 1.5.1 人生阶段

| 阶段 | 年龄 | 内容重点 | 参考时长 | 可否跳过 |
|---|---|---|---|---|
| 婴 | 0–2 | 被动、育儿选择 | 0.5–1 h | 部分 |
| 童 | 3–11 | 特质形成、家庭互动 | 2–3 h | 大量 |
| 少年 | 12–17 | 学业、初恋、叛逆 | 3–4 h | 部分 |
| 青年 | 18–29 | 职业、独立、婚恋 | 6–8 h | 少量 |
| 壮年 | 30–49 | 事业高峰、育儿 | 5–7 h | 少量 |
| 中年 | 50–64 | 转型、子女离家 | 3–4 h | 部分 |
| 老年 | 65+ | 传承准备、回顾 | 2–3 h | 部分 |

单代约 15–25 小时，跳过无决策价值的时段可压到 10 小时以内。

#### 1.5.2 遗传

| 维度 | 规则 | 目的 |
|---|---|---|
| 外貌 | 父母特征混合 + 5% 突变 | 让"像爸爸/像妈妈"成为话题 |
| 特质 | 父母特质池各取 1 → 2 选 1；10% 概率出隐性特质 | 制造意外 |
| 潜能 | 技能上限的隐藏加成，来自祖辈累计（隔代遗传） | 让"家族培养"有意义 |
| 家族倾向 | 连续两代从事同一职业 → 家族声望加成 | 长线身份认同 |

#### 1.5.3 传承仪式

老年阶段触发，是全代唯一不可逆的选择，也是情感高点：

1. **选继承人**：决定玩家下一代控制谁（可违背长幼顺序，产生家族矛盾）。
2. **分遗产**：房产 / 存款 / 传家物（传家物带一条"祖先记忆"，给持有者情绪源）。
3. **立家训**：写一句格言，给全族一个永久 buff + 一个永久 debuff（如"吃亏是福"：关系 +10%，收入 -5%）。

**设计理由**：把"死亡"从失败变成"选择与交接"，同时完成系统的软重启（数值重置、内容解锁）。

#### 1.5.4 家族树

可视化 + 每人一句自动生成的小传（基于其最高技能、最重记忆、最大成就）。这是天然的社交分享素材，也是玩家回看的"意义凭证"。

### 1.6 新手与深化：双轨设计

#### 新手（前 60 分钟）

| 设计 | 具体做法 | 解决的问题 |
|---|---|---|
| 首日清单 | 只给三件事：吃饭、洗澡、睡够 | 降低首个循环的理解成本 |
| 日程模板 | 一键套用"上班族 / 学生 / 自由职业" | 跳过最难的空白页 |
| 需求预警 | 需求 < 30 时角色主动开口提议，点击直达 | 把"管理"变成"回应" |
| 自动补位 | 队列空转时按优先级自动补一个行动（可关） | 避免罚站式空转 |
| 情绪解释 | 点情绪图标 → 展开"因为哪 3 件事" | 对抗黑箱感 |
| 随机按钮 | 创建角色时每个步骤都有"帮我选" | 降低决策疲劳 |

#### 深化（10 小时后）

| 设计 | 具体做法 |
|---|---|
| 情绪连携 | 同象限两个情绪源叠加 → 触发"罕见情绪"（如兴奋 + 疲惫 = 亢奋），解锁特殊行为 |
| 家族秘辛 | 每代随机生成 1 条家族历史，影响后代特质（"你祖父的那场火灾"） |
| 社区风评 | 家族声望改变 NPC 行为、商店价格、子女入学 |
| 建造主题 | 房间标签组合出主题（书房 + 茶室 = "静心"，情绪恢复 +50%） |
| 挑战开局 | 单亲 / 破产 / 三代同堂，改初始条件而非难度数值 |

## 2. 流程与画面设计

### 2.1 完整流程

| 阶段 | 玩家做什么 | 时长 | 关键界面 | 情绪目标 |
|---|---|---|---|---|
| 1. 开场 | 看一段"家族相册"过场 | 30 s | 全屏播片 | 建立"我要延续一个家族"的预期 |
| 2. 创建角色 | 基因 → 外貌 → 特质 → 志向 → 初始关系 | 3–8 min | 分层创建器 | 表达欲 |
| 3. 落地 | 选地块（3 选 1）→ 空房或预制小屋 → 初始资金 | 2 min | 街区俯瞰 | 期待 |
| 4. 首日 | 跟着引导完成三件事 | 10–15 min | 主场景 + 引导卡 | 上手成就感 |
| 5. 日常 | 排日程 → 干预 → 建造 | 主体 | 主界面 | 掌控感 |
| 6. 节点 | 生日 / 节日 / 职场 / 关系事件 | 3–5 min/次 | 半模态或全屏 | 惊喜与张力 |
| 7. 阶段结算 | 看"成绩单"：技能 / 关系 / 财务 / 心愿 | 1–2 min | 结算面板 | 被认可 |
| 8. 传承 | 选继承人 → 分遗产 → 立家训 | 3–5 min | 传承仪式 | 情感高点 |
| 9. 长线 | 家族等级提升，解锁新地块 / 职业 / 家具包 | 持续 | 家族档案 | 长期目标 |

**关键约束**：以上每一步都是可存档状态。玩家在创建角色的第 3 步关掉网页，回来必须还在第 3 步。

### 2.2 界面层级与布局

#### 2.2.1 四层 Z 序

| 层 | 内容 | 是否暂停时间 | 叠加上限 |
|---|---|---|---|
| **L0 世界层** | 3D 场景、角色、特效 | — | — |
| **L1 HUD 常驻层** | 角色卡、行动队列、时间控制、心愿、菜单 | 否 | 固定 |
| **L2 面板层** | 角色 / 关系 / 技能 / 日历 / 建造目录 | 否（半模态，压暗世界） | 1 个 |
| **L3 模态层** | 事件对话、阶段结算、传承、设置 | 是 | 1 个 |

**规则**：
- 打开 L2 不暂停时间——避免玩家把面板当暂停键，也保证"日子在过"的体感。
- L3 必须提供"稍后处理"（结算与传承除外）。
- L1 常驻块不超过 5 个，其余收进菜单。

#### 2.2.2 主界面布局（桌面 16:9）

- **顶部 8%**：状态条（家族名 / 日期 / 天气 / 现金），细长、低对比。
- **左上**：菜单与建造入口（图标）。
- **左下**：当前角色卡（头像 + 4 个需求环 + 情绪图标 + "为什么"入口）。
- **底部中央**：行动队列（横向 chips，可拖拽排序、可取消）。
- **右下**：时间控制（暂停 / 1x / 3x / 快进）。
- **右上**：心愿与目标（最多 3 条）。
- **中心 70%**：世界，四周留 4% 安全边作为"书页留白"。

#### 2.2.3 建造模式布局

| 区域 | 内容 |
|---|---|
| 左侧 24% | 目录树：房间 / 家具 / 装饰 / 材质，带搜索与"适用房间"筛选 |
| 底部 12% | 工具栏：选择 / 墙 / 地板 / 门 / 移动 / 复制 / 删除 / 撤销 / 网格 |
| 顶部 6% | 楼层切换、预算、保存与退出 |
| 中央 | 网格视图；墙体自动剖切（遮挡视线的墙淡出） |
| 右侧浮层 | 选中物品卡：价格 / 功能 / 情绪影响 / 尺寸 / 美观分 |

交互：拖拽放置 + 自动吸附 + 旋转（R / 双指 / 肩键）；框选批量移动；"房间模板"一键填充。

#### 2.2.4 交互 HUD 与情境轮盘

点击物体不弹菜单，而是弹**情境轮盘**（6–8 个扇区），这是唯一同时适配鼠标、触屏、手柄的交互形态：

- 鼠标：右键或直接点物体唤出，扇区悬停即高亮
- 触屏：长按 200ms 唤出，扇区放大到 56pt
- 手柄：按住 LT 唤出，左摇杆选择

轮盘扇区按"当前需求 / 情绪"动态排序——饿了就把"吃"放第一位。这是最便宜的"智能感"。

#### 2.2.5 结算面板

三栏结构：**左 数据**（技能 / 财务 / 关系变化）｜ **中 叙事**（自动生成的一段"这几天发生了什么"）｜ **右 下一步**（2–3 条建议目标）。底部一个大按钮"继续"。

日终小结用"手账翻页"动效，一天一页，可回翻最近 7 天——把数据变成可读的故事。

### 2.3 画面风格与视角

#### 2.3.1 视角

3/4 等距俯视，环绕仅限水平 360° + 俯仰 25°–65°，无第一人称。

**理由**：
1. 建造与多角色同屏需要全局视野；
2. 限制视角大幅降低美术与性能成本（不用做天花板、背面细节）；
3. 固定俯仰让家具摆放判断变得直觉。

**镜头控制**：

| 操作 | 键鼠 | 触屏 | 手柄 |
|---|---|---|---|
| 平移 | 拖拽 / 边缘推屏（可关） | 单指拖 | 右摇杆 |
| 缩放 | 滚轮（3 档：房间 / 楼层 / 街区） | 双指捏合 | 扳机 |
| 旋转 | 中键拖 / Q E | 双指旋转 | 左右肩键 |
| 聚焦 | 双击角色 | 双击 | Y 键循环角色 |
| 机位记忆 | 数字键 1–4 | — | 十字键 |

#### 2.3.2 美术方向：「立体绘本 / 微缩剧场」

- 每个地块是一块**漂浮的立体书页**，边缘有纸张层叠与书脊；镜头拉远能看到"书页"轮廓，镜头拉近像在看一个纸雕模型。
- 低多边形 + 手绘贴图（512–1024），可选描边，高饱和但明度柔和的配色。
- 日夜用色温渐变 + 窗光投影，不做全局实时光照。
- 角色 6 头身卡通比例，面部用贴图表情切换（不做面部骨骼），动画 12 帧关键帧 + 混合树。

**为什么选这个方向**：
1. 低模 + 手绘在 Web 上能做到 60fps；
2. 风格化天然规避"拟真人物恐怖谷"；
3. "书页 / 剧场"与"手账式 UI"同源——整个产品共用一套世界观：**你在翻阅一个家族的书**。

#### 2.3.3 视觉层次

可交互物体默认只有鼠标悬停时显示"描边 + 悬浮图标"；与当前需求相关的物体常驻一个极淡的呼吸光点。避免满屏图标破坏画面。

### 2.4 UI 视觉风格

| 项 | 规格 |
|---|---|
| 主题 | 生活手账（Planner）：米白纸底、细网格、彩色索引标签、胶带与回形针装饰 |
| 标题字 | 手写体（仅标题与数字），正文无衬线 |
| 主色 | 暖米 #F7F3EC |
| 强调色 | 珊瑚红 #E2725B / 湖蓝 #5B8FA8 / 苔绿 #7A9A6B |
| 情绪色 | 独立一套 8 色，与 8 象限一一对应，全局唯一含义 |
| 组件 | 卡片圆角 12px，投影极轻，线性图标 2px |
| 动效 | 150–250ms，ease-out，面板"抽纸"式入场 |
| 可读性 | 正文 ≥ 14px（移动 15px），对比度 ≥ 4.5:1，不用纯白纯黑 |

**一致性策略**：UI 的"标签 / 贴纸"语言复用到建造模式、关系图、家族树，形成品牌记忆点，也让后期新增界面不必重新设计。

## 3. 游戏形式与系统

### 3.1 建造 / 布置系统

#### 3.1.1 基础规则

- 网格 0.5 m，墙高 2.8 m，楼层高 3.0 m。
- **自动房间识别**：封闭区域自动成为房间，可命名、可打标签（卧室 / 书房 / 厨房 / 浴室 / 客厅 / 工作室）。
- **三层放置**：结构（墙 / 门 / 窗 / 地板 / 楼梯）→ 家具（带功能槽）→ 装饰（纯情绪与美观）。

#### 3.1.2 功能槽（数据驱动的核心）

每件家具声明四件事：**提供哪些交互 / 满足哪个需求 / 影响哪个情绪 / 占多大空间**。

新增一件家具 = 新增一行配置，不改任何逻辑代码。这让内容产能成为唯一瓶颈，而不是程序排期。

#### 3.1.3 房间标签 → 情绪光环

| 标签 | 光环效果（在房间内时） |
|---|---|
| 卧室 | 体力恢复 +20% |
| 厨房 | 饱腹恢复 +15%，烹饪 +10% |
| 书房 | 专注 +1 级情绪源 |
| 浴室 | 整洁恢复 +25% |
| 工作室 | 创作类行为 +20% |

**组合主题**：书房 + 茶室 = "静心"（情绪恢复 +50%）；厨房 + 餐厅 = "待客"（社交成功率 +15%）。组合是免费的深度，也是玩家"想试试别的组合"的动机。

#### 3.1.4 门槛设计：双模式

- **套件模式（默认）**：一键放一整套厨房 / 卧室，玩家只需选风格与预算。
- **自由模式**：逐件摆放、调色、改材质。

设计理由：建造是同类产品最大的流失点之一。必须先给"结果"（我有个像样的家），再给"自由"（我要把它变成我的）。

#### 3.1.5 蓝图与 UGC

- 房间 / 整屋可保存为蓝图，生成短链分享，他人一键导入（Web 端的天然优势）。
- 官方每周放出 3 套精选蓝图，作为 UGC 冷启动的种子。
- 美观分 = 家具美观值 + 搭配加成 + 主题完成度，影响"兴致"与访客评价。

### 3.2 职业与技能系统

#### 3.2.1 职业结构

| 类型 | 路线 | 上班形式 |
|---|---|---|
| 主线 | 商务 / 医护 / 科技 / 艺术 / 餐饮 | 兔子洞（角色离开 6–8 小时） |
| 自由 | 写作 / 绘画 / 直播 | 在家可操作，按订单交付 |

每条主线 6 级，每级 2 个分支选择（如"管理线 / 专业线"），让同职业有不同结局。

#### 3.2.2 为什么是兔子洞 + 每日一次决策

Web 端不适合长时间操作职场，但完全跳过会失去"在场感"。折中方案：上班期间角色消失，但每天弹**一次工作事件**（加班 / 摸鱼 / 帮同事），用 1 次决策换取参与感，成本极低。

#### 3.2.3 绩效公式（可解释）

绩效 = 技能等级 40% + 情绪状态 20% + 人脉关系 20% + 随机事件 20%

让"上班前洗个澡、保持好心情、和同事吃个饭"都有明确回报——这是需求系统与职业系统的连接点。

#### 3.2.4 育儿

孩子的技能成长由「陪伴时长 × 教养风格」决定。教养风格（严格 / 宽松 / 放养）在儿童期锁定，影响少年期特质与成年后的关系模式。

设计理由：让"代际"不只是数值继承，而是**行为模式的传递**——这是本作最有情感重量的部分。

### 3.3 社交与家庭关系

#### 3.3.1 对话系统

- 一次对话 = 3 轮（开场 / 深入 / 收尾），每轮消耗 15–30 游戏分钟。
- 每轮从 4–6 张**话题卡**中选 1 张（按关系、情绪、场景、记忆生成），再选语气（友好 / 幽默 / 直接）。
- 成功率 = 基础 50 + 关系修正 + 技能修正 + 情绪修正 + 记忆修正。
- **失败不直接扣好感，而是积累"张力"**。张力是戏剧燃料，不是惩罚条。

#### 3.3.2 恋爱与婚姻

吸引（外貌 / 特质匹配）→ 暧昧（3 次成功互动）→ 交往（信任 ≥ 60）→ 同居 / 结婚（双方心愿都满足）。

每一步都有"被拒绝"的可能，且拒绝会留下记忆条目——这让追求过程有真实的风险感。

#### 3.3.3 家庭运营

- **家务分工**：自动分配或手动指派，长期不均会产生"委屈"情绪源。
- **家庭会议**：每周一次，分配预算与家庭目标（换房 / 生子 / 旅行），完成后全家情绪 +。
- **家庭矛盾**：长期低信任 → 冷战事件 → 需要玩家主动调停（选边或和稀泥，都有代价）。

#### 3.3.4 NPC 生态

街区 NPC 有简化版一日日程（上班 / 回家 / 逛街），会主动来访、送礼物、传闲话。

设计理由：这是让世界"活着"的最低成本方案——不需要复杂 AI，只需要"在对的时间出现在对的地方"。

### 3.4 事件与剧情触发

#### 3.4.1 三类事件

| 类型 | 触发 | 例子 | 作用 |
|---|---|---|---|
| 即时事件 | 需求驱动、低概率 | 打翻咖啡、水管漏水 | 打断与调味 |
| 日程事件 | 日历预告 | 生日、面试、家长会、节日 | 让玩家提前准备 |
| 叙事事件 | 状态条件满足 | 信任 < 20 且同住 → 冷战；连续 7 天兴致 < 30 → 倦怠期 | 主要剧情来源 |

#### 3.4.2 触发机制

条件表：前置条件 + 权重 + 冷却时间 + 互斥组。

**戏剧预算（Drama Budget）**：每天最多 2 个"重要事件"、5 个"小事"，超出排队到次日。

设计理由：事件密度是体验命脉——过密变噪音，过疏变空转。用配额而不是纯概率，才能保证节奏可控。

#### 3.4.3 表现分级

| 级别 | 表现 | 例子 |
|---|---|---|
| 小事 | toast + 角色气泡 | 打翻咖啡 |
| 重要 | 底部滑入半模态卡片，2–3 个选项 | 同事借钱 |
| 关键 | 全屏模态 + 插画 | 求婚、失业、传承 |

#### 3.4.4 选项设计原则

每个选项都必须有"短期好 / 长期坏"或反之的张力，**禁止明显的正确答案**。

示例：升职机会 → 加班（+钱 +晋升，-体力 -家庭关系）/ 回家陪孩子（+关系，-晋升进度）/ 推给同事（+时间，-信任）。

### 3.5 存档与读档

#### 3.5.1 结构

**快照 + 命令日志**：

- 快照：每 5 游戏分钟或关键事件后生成全量状态。
- 命令日志：记录玩家所有操作意图，加载时"快照 + 重放"。

**理由**：体积小、可回放、天然支持"人生时间线"回看、便于服务端校验与防作弊。

#### 3.5.2 槽位

3 个手动 + 1 个自动 + 1 个"传承存档"（只读，记录每代结束状态，用于跨代对比与分享）。

#### 3.5.3 版本迁移

- 存档携带 `schemaVersion`，配置表携带内容版本。
- 加载时执行迁移函数链（v1 → v2 → v3）。
- 无法迁移时以"只读模式"打开——可看、可截图、不能继续。这比"存档损坏"的体验好得多。

#### 3.5.4 防作弊与崩溃恢复

- 服务端权威时间：离线时长由服务端计算，客户端只提交"我做了什么"，不提交"过了多久"。
- 命令日志逐条落盘，崩溃后回放至最后一条，损失 ≤ 1 游戏分钟。

## 4. 跨平台架构

### 4.1 分层设计

| 层 | 职责 | 依赖限制 | 可替换性 |
|---|---|---|---|
| **内容层** | 配置表（特质 / 家具 / 事件 / 对话 / 职业），CSV 导入 + schema 校验 | 无 | 策划可独立迭代 |
| **模拟层** | 纯逻辑：tick、需求、情绪、关系、事件判定 | 不得引用渲染库 / DOM / 平台 API | 可跑在浏览器、服务端、原生壳 |
| **表现层** | 订阅模拟层事件，映射为动画 / 音效 / 特效 | 只读模拟状态 | 可整体替换 |
| **视图层** | HUD 与面板，绑定视图模型 | 不直接改数据 | 各端可重写 |
| **平台层** | 输入 / 存储 / 生命周期 / 音频 / 网络 / 分享 / 支付 / 震动 | 通过接口注入 | 每端一个实现 |

**核心原则：模拟层是唯一真相（Single Source of Truth）。**

它只吃"命令"、只吐"事件"，由此获得四项能力：
1. 同一份逻辑可在服务端跑离线结算与反作弊；
2. 天然支持录像回放与"人生时间线"；
3. 可用脚本批量模拟，做数值平衡测试（跑 10000 次人生看分布）；
4. 换引擎时逻辑零改动。

### 4.2 输入方案

统一"输入意图（Input Intent）"抽象，业务层永远不直接读键鼠。

| 意图 | 键鼠 | 触屏 | 手柄 |
|---|---|---|---|
| 指向 | 鼠标移动 | 手指按下 | 虚拟光标（左摇杆） |
| 确认 | 左键 | 单击 | A |
| 取消 | 右键 / Esc | 双指捏合返回 | B |
| 拖拽 | 按住拖 | 长按 200ms 后拖 | 按住 A + 摇杆 |
| 情境轮盘 | 右键 | 长按 | 按住 LT |
| 时间加速 | 空格 | 双击时间条 | RB |
| 建造旋转 | R | 双指旋转 | 肩键 |
| 切换角色 | Tab / 数字键 | 点头像 | Y / 十字键 |

**硬性规则**：所有功能必须能用「焦点 + 方向 + 确认」完成。这既是无障碍要求，也是主机适配的最低门槛。

**信息补位**：
- 鼠标：悬停即预览
- 触屏：长按 300ms 预览
- 手柄：焦点停留 400ms 自动展开提示

### 4.3 分辨率与 UI 自适应

| 断点 | 设备 | 布局策略 |
|---|---|---|
| < 600 px | 手机竖屏 | 卡片式：世界上半屏，日程/需求下半屏 |
| 600–1024 px | 手机横屏 / 平板 | 抽屉式面板，HUD 收起为图标条 |
| 1024–1600 px | 笔记本 | 标准布局 |
| > 1600 px | 桌面 / 超宽 | 侧栏常驻，世界居中并限制最大宽度 |

技术策略：
- HUD 用「锚点 + 安全区」定位，不写死像素。
- 面板双形态：窄屏抽屉、宽屏侧栏（同一套组件，两种容器）。
- 尺寸用 rem 基准 + 容器查询，字体随容器缩放。
- 3D 相机按视口宽高比调整 FOV 与俯仰角，保证关键区域始终可见。
- 覆盖刘海、圆角、手势条安全区；超宽屏两侧用"书页边缘"装饰填充。

**首个版本只做桌面 + 平板横屏**，手机竖屏的卡片模式排到 P1——这是明确的范围裁剪，不是遗漏。

### 4.4 性能优化策略

#### 4.4.1 预算表

| 指标 | 桌面目标 | 移动目标 |
|---|---|---|
| 帧率 | 60 fps | 30–60 fps |
| Draw call | ≤ 150 | ≤ 80 |
| 三角面 | ≤ 300k | ≤ 120k |
| 同屏角色 | ≤ 8 | ≤ 5 |
| 粒子 | ≤ 200 | ≤ 60 |
| 纹理常驻 | ≤ 150 MB | ≤ 80 MB |
| 首包 | < 20 MB | < 15 MB |

#### 4.4.2 关键手段

| 手段 | 做法 | 收益 |
|---|---|---|
| 模拟/渲染解耦 | 模拟 10 Hz 固定步长，渲染 60 Hz 插值 | 逻辑稳定，帧率波动不影响玩法 |
| 模拟移出主线程 | 放入 Worker（或服务端） | 主线程只做渲染，避免卡顿 |
| 房间级剔除 | 只渲染当前房间 + 可见邻间 | 室内场景 draw call 降 60%+ |
| 静态合批 | 静态家具按材质合并；同类用实例化渲染 | 大幅降低 draw call |
| 遮挡墙淡出 | 改透明度而非销毁重建 | 避免卡顿 |
| 光照简化 | 1 个方向光 + 烘焙 AO；阴影用 blob + 单级 shadow map | 省掉最贵的一档 |
| 按需流式加载 | 首屏只加载当前地块，家具贴图按房间加载 | 首包体积可控 |
| 压缩 | 模型 Draco、贴图 KTX2、音频 Opus | 包体降 50–70% |
| 移动降级 | 关阴影、渲染 0.75x、降粒子、锁 30fps | 保住可玩性 |

#### 4.4.3 网络与离线

- 存档增量同步（只传命令日志增量）。
- 断线时本地继续，恢复后补传；单机体验不因网络中断。
- 离线结算在服务端完成，客户端只负责展示结果。

### 4.5 架构层必须做对的抽象

这 8 条如果一开始做错，后期修改成本极高——它们是"多端扩展"的真正门槛。

| # | 抽象 | 做错的后果 |
|---|---|---|
| 1 | 逻辑层与渲染层彻底分离 | 无法上主机，无法服务端结算 |
| 2 | 命令 / 事件模型 | 存档、回放、联网、自动化测试全部要重写 |
| 3 | 平台能力矩阵 + 特性开关 | 代码里到处是平台判断分支，无法维护 |
| 4 | 内容 ID 稳定化（字符串 ID，不用数组下标） | 内容一迭代就炸老存档 |
| 5 | 统一单位与坐标系（1 单位 = 1 米，Y 轴向上） | 美术、关卡、物理三方对不上 |
| 6 | 时钟与随机数可注入 | 无法复现 bug、无法回放、无法做平衡测试 |
| 7 | UI 通过视图模型通信，不直接改数据 | 多端 UI 无法重写，等于绑死一个平台 |
| 8 | 本地化从第一天做（文案表 + 占位符规范） | 后补成本是前期做的 5–10 倍 |

### 4.6 多端演进路线

| 版本 | 形态 | 复用度 | 主要工作 |
|---|---|---|---|
| V1 | Web（PWA 可安装） | — | 全部自研 |
| V1.5 | 桌面端（Tauri / Electron 壳） | 逻辑 + 表现 + UI ≈ 100% | 打包、原生菜单、文件系统 |
| V2 | 移动端 | 逻辑 100%，HUD 重做 | 触屏交互、竖屏卡片模式、性能降级 |
| V3 | 主机端 | 逻辑 100%，渲染层替换 | 手柄 UI、性能与认证要求、存档服务 |

## 5. MVP 范围建议

**原则**：先证明「日程 + 情绪 + 关系」这个三角成立，再堆内容。

### 5.1 P0：必须实现

| # | 模块 | 最小实现 | 为什么必须 |
|---|---|---|---|
| 1 | 时间与日程 | 3 档速度、自动暂停、日程块拖拽 | 核心差异化，不做就没有产品辨识度 |
| 2 | 需求 + 情绪 | 4 条需求、8 象限、5 类情绪源 | 核心反馈循环 |
| 3 | 交互与队列 | 点选物体、行动排队、20 个可交互对象 | 最基础的"动词" |
| 4 | 简易建造 | 放置 / 移动 / 删除 / 旋转 + 30 件家具 + 1 间房 | 表达欲的最小满足 |
| 5 | 职业与技能 | 1 条自由职业线（绘画）+ 3 个技能（绘画 / 烹饪 / 社交） | 提供目标感与时间消耗出口 |
| 6 | 关系 | 1 个 NPC、三轴关系、10 张话题卡 | 验证"关系会记事" |
| 7 | 事件 | 3 小 + 3 中 + 2 大，含戏剧预算 | 制造惊喜，验证节奏 |
| 8 | 云存档 | 1 自动 + 1 手动 + 离线摘要 | Web 端必需，否则会丢档 |
| 9 | 新手引导 | 首日三件事 + 日终小结 | 直接决定次日留存 |
| 10 | 代际钩子 | 1 个简化传承节点（结婚或生子二选一） | 验证长线动机是否成立 |

**验收标准**：新玩家 30–45 分钟能完整体验一个"人生片段"，2–3 小时能触达第一次传承并产生"想继续"的意愿。

### 5.2 P1：第二迭代

- 多角色切换与家庭预算
- 第二条职业线、第 4–6 个技能
- 建造蓝图分享与导入
- 节日系统与季节变化（视觉层面）
- 儿童期与育儿（教养风格）
- 家族树与"一句话小传"
- 手机横屏适配

### 5.3 P2：明确延后

| 功能 | 延后理由 |
|---|---|
| 多人 / 联机 | 与"私人生活模拟"的核心体验冲突，投入产出比低 |
| 宠物 | 内容成本高，玩法增量小 |
| 完整遗传与外貌混合 | 需要大量美术资源，MVP 阶段收益低 |
| 玩家 UGC 市场 | 需要审核、经济与反作弊体系，属于平台化能力 |
| 主机 / 竖屏 | 端适配成本高，需先验证核心玩法 |
| 语音与自由文本对话 | 成本与不可控性极高，卡牌对话已足够 |
| 复杂剧情脚本 | 先让系统自己生成故事，再考虑手工剧情 |
| 多街区 / 开放世界 | 与"微缩剧场"美术方向冲突 |

### 5.4 验证指标

| 维度 | 指标 | 目标 |
|---|---|---|
| 上手 | 引导完成率 | ≥ 70% |
| 理解 | 首日日程功能使用率 | ≥ 50%（证明差异化被感知） |
| 留存 | D1 / D7 | ≥ 30% / ≥ 10% |
| 会话 | 平均时长 | 12–20 分钟 |
| 表达 | 建造时长占比 | 15–25%（过低=表达不足，过高=玩法空心） |
| 叙事 | 日终小结查看率 | ≥ 60% |
| 平衡 | 事件选项分布 | 无单一选项占比 > 55% |
| 技术 | 首屏加载（4G） / 崩溃率 / 60fps 占比 | < 5s / < 0.5% / > 90% |

### 5.5 主要风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| **内容量陷阱** | 系统太薄，玩家 2 小时看穿全部 | 把"系统交互"当内容：技能协同、情绪连携、房间主题，用组合爆炸换内容量 |
| **日程变"看片"** | 排完日程后无事可做 | 每个日程块至少埋 1 个决策点；允许随时打断 |
| **Web 性能与包体** | 首屏慢、掉帧 | 低模 + 手绘 + 流式加载，首包 < 20 MB |
| **情绪黑箱** | 玩家不理解角色为何难过 | 永远提供"为什么"展开，情绪源 ≤ 5 个 |
| **存档兼容** | 内容迭代炸老档 | ID 稳定 + 迁移链 + 只读降级 |
| **代际情感稀释** | 玩家对后代无感 | 让传承仪式成为唯一不可逆选择，并保留传家物记忆 |

## 附录 A：待定问题（需在 MVP 前决策）

1. **商业模式**：买断 + 家具包 / 订阅 / 免费 + 内购。这会反向影响建造内容节奏与"套件模式"的设计权重。
2. **童年跳过尺度**：允许大幅跳过会提高节奏，但会稀释代际情感浓度，需要 A/B 验证。
3. **文案语气**：手账文艺风 vs 轻网感吐槽风，需在首日引导做小规模测试。
4. **街区规模**：MVP 单地块 vs 4 户小街区。后者能验证 NPC 生态，但成本翻倍。
5. **是否做"回看人生时间线"**：这是命令日志架构的免费红利，但需要额外的 UI 设计。
